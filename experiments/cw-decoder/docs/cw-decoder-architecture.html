Region-Isolated Streaming for Real-World CW Copy

A practical decoder architecture that holds 100% copy on multi-burst, mixed-speed off-air audio with operator pauses

Randy Treit, KC7AVA — with collaboration from the QsoRipper agent toolchain

QsoRipper Project · experiments/cw-decoder

Abstract. Off-air CW audio rarely behaves like a textbook practice file. An operator sends a short burst at 13 WPM, pauses through 1–3 seconds of band hiss, then sends another burst at 30 WPM, then pauses again. Most streaming decoders — including our own earlier “V3 envelope” foundation — handle the first burst well, but smear the second through residual lock state, mis-classify dits and dahs at the new speed, or hallucinate “ghost” characters from the static between bursts. This report describes a region-isolated streaming architecture that detects each active CW burst as a discrete region, decodes each region independently with its own pitch and speed lock, and only commits the region’s text to the transcript once a trailing-static window confirms the burst has ended. The architecture preserves the rich visualizer event stream of the previous foundation, runs in true real-time on a stock laptop, and delivers a 100% character-exact transcript on the target multi-burst reference recording.

1. The Problem

QsoRipper is a keyboard-first ham-radio logging system whose CW subsystem must do two things at once: paint a visualization of what the radio is hearing right now (waveform, lock state, classified elements, current and historical WPM) and append a clean text transcript of every Morse character that actually came through. The visualizer is forgiving — it is fine to show a flicker when the band changes — but the transcript is not. Operators rely on it for contest exchanges, callsign capture, and post-QSO reconstruction. A single ghost word at the start of a transmission is worse than no decode at all.

The reference test case for this work is radio-20260502-105714.mp3, an off-air capture from the author’s Kenwood TS-590SG. The file contains four CW bursts at visibly different speeds, separated by background hiss:

  1. IHU — ~13 WPM
  2. NVCHU — ~8 WPM
  3. 7QP W7N — ~30 WPM
  4. 7QP W7N — ~30 WPM (repeat)

The ground-truth file radio-20260502-105714.truth.txt is the operator’s canonical copy: IHU NVCHU 7QP W7N 7QP W7N. The success criterion was simple: produce that string, character for character, when the same audio is streamed through the production logger’s F7 live-mic capture path. Anything less — a missing letter, a ghost letter, a merged word — was treated as failure.

2. Why the Previous Foundation Came Up Short

The pre-existing “V3 envelope” decoder (stream-live-v3) is built around a single LiveEnvelopeStreamer that ingests audio continuously, estimates a Goertzel envelope at the locked pitch, runs a percentile-based hysteresis state machine to classify on/off intervals, and feeds a k-means dot/dah classifier with a sample-indexed commit cursor. It is excellent at painting the visualizer and at producing a stable transcript on long, single-speed transmissions. It powers the cw_decode_rx_wpm field that the production logger writes to ADIF as APP_QSORIPPER_RX_WPM.

On radio-20260502-105714.mp3, however, V3 produced a transcript that drifted progressively further from truth as it moved from burst to burst. The root causes were structural:

  • Sticky speed lock. The locked WPM from burst 1 (13 WPM) is still the working hypothesis when burst 2 starts at 8 WPM. The k-means classifier mis-labels dahs from the slower burst as dits, dits as inter-element gaps.
  • Stale noise floor. The percentile-based noise/signal floors are estimated over a sliding window. When static between bursts dominates the window, the threshold drifts and trailing dits of the previous burst can re-fire as ghost elements.
  • Append-cursor smearing. The sample-indexed commit cursor advances monotonically. If a region decodes wrong on the first pass, that wrong decode is locked into the transcript — later cycles cannot undo it without producing a worse artifact (the “TSA USA EE TSA USA EE” ghost-repeat pattern).

A natural fix was to add more tuning knobs to V3: tighter relock thresholds, more aggressive noise-floor decay, content-stability gates on the commit cursor. Each of those helped a little and broke something else. After several rounds of this, we stepped back and considered a different decomposition.

3. Region-Isolated Decoding

The insight is that real-world QSO audio is naturally segmented by the operator. A burst is a discrete unit of intent: the operator keys, sends some elements, releases. Between bursts, the receiver sits in band noise. If we could detect those bursts as regions and decode each region independently — with its own fresh pitch lock, its own k-means classifier, its own WPM estimate — the cross-burst contamination disappears by construction. There is nothing to leak.

3.1 Detection

Region detection is implemented in region_stream.rs::decode_region_stream. The function performs a coarse Goertzel pitch sweep over the entire buffer, picks the dominant tone, and computes a frame-level energy envelope at that pitch. From the envelope it derives two robust floors via percentiles: 

noise_floor  = quantile(env, 0.30)
signal_floor = quantile(env, 0.95)
threshold    = noise_floor
             + threshold_factor × (signal_floor - noise_floor)

With threshold_factor = 0.30, the decision boundary sits 30% of the way up the dynamic range — well clear of band noise, well below saturation. Frames above threshold are marked “active”. Active runs are merged across short gaps (merge_gap_s = 0.5 s by default), and runs shorter than min_region_s = 0.3 s are rejected as transient static spikes. Each surviving run is padded symmetrically by pad_s = 0.15 s so leading and trailing dits are not clipped.

A later synthetic impairment sweep added one more guard that belongs in the baseline: before a detected run is decoded, it must show narrowband CW-like prominence. The implementation compares Goertzel power at the selected pitch against the run’s broadband frame energy and rejects runs below min_tonal_prominence_ratio = 8.0. This prevents pure background static from being promoted into fake regions simply because a percentile threshold can always split random noise into “above” and “below” frames.

3.2 Per-region decode

For each detected region, the audio slice is handed to the ditdah baseline decoder with no carry-over state. The decoder estimates pitch and dot length fresh, runs its own k-means classification, and emits a transcript fragment. Because each region is short and homogeneous (one operator, one burst, one speed), the baseline decoder — which was always strong on short clean clips — performs near-perfectly.

3.3 The streaming wrapper

region_streamer.rs wraps the batch detector for true streaming use. It maintains a rolling sample buffer; on every try_commit() call it re-runs detection over the current buffer and reports any region whose end time is followed by at least stable_latency_s = 0.6 s of trailing static. That trailing-static window is the commit gate — it guarantees that no further morse from the same burst can still be arriving when we lock in the region’s text. 

// Append-only commit, deduplicated across decode cycles.
for region in detected:
    if region.start ≤ last_committed_end:
        continue                    // already committed
    if region.end > head - stable_latency:
        break                       // not stable yet
    transcript.append(region.text)
    last_committed_end = region.end

For long-running live capture, trim_committed() drops the buffer back to a configurable lookback (default 6 s past the last committed region), and reset() clears all state in response to the operator’s Ctrl+Alt+W relock request, all without restarting the decoder process.

4. Integration with the V3 Visualizer

A key design constraint was that the visualizer must keep working. Operators rely on the live waveform, the lock indicator, the pitch readout, and the rolling WPM gauge to know whether the decoder is healthy. The V3 envelope path produces all of those as a side effect of its frame-level processing; the region streamer produces none of them.

The integration therefore runs both decoders in parallel. The new --region-transcript flag on stream-live-v3 instantiates a RegionStreamer alongside the existing LiveEnvelopeStreamer. Audio chunks are fed to both. The envelope streamer continues to emit NDJSON viz frames on every decode cycle, exactly as before. The region streamer’s try_commit() result overrides only one field on the emitted text / appended / end events: the cumulative transcript string.

Both UI surfaces — the production logger’s CwDecoderProcessSampleSource and the experimental visualizer’s CwDecoderProcess — spawn the decoder with --region-transcript by default. Operators do not see a new mode switch; they simply get a transcript that matches what they actually heard.

It generates deterministic CW with quiet static gaps, additive white noise, QSB amplitude fading, an offset continuous-tone QRM carrier, and a combined noise/QSB/QRM exchange. 6. Discussion

6.1 Latency

The trailing-static commit gate trades latency for correctness. With stable_latency_s = 0.6 s, a region’s text appears in the transcript roughly 0.6 s after the operator releases the key at the end of a burst. For logging and post-QSO copy this is negligible. For real-time pile-up triage it would be perceptible; the parameter is exposed as --region-stable-latency-s and can be reduced at the cost of occasional re-decode churn.

6.2 Why batch and stream agree on real CW

The streaming wrapper and the batch reference call the same decode_region_stream over the same audio. The only difference is that the streaming wrapper invokes it incrementally on a growing buffer. As long as the noise-floor percentiles are stable across cycles — which they are once a real CW signal is present — the detected regions are identical and the per-region decoder is deterministic. On clips with no real signal, the percentiles drift with the buffer length and incremental commits can capture transient noise spikes that the batch reference smooths out.

6.3 Relation to the append-only event-stream foundation

The append-only event-stream decoder in append_decode.rs is not deprecated. It remains the source of truth for the visualizer’s bar painting and for the time-weighted cw_decode_rx_wpm aggregator that feeds ADIF. The region-isolated path supplements that foundation for the transcript field; the two are now both “line in the sand” baselines, each governing its own concern.

7. Future Directions

Several extensions are natural next steps:

  • Content-stability gate. Require a candidate region to produce identical decoded text across N consecutive try_commit cycles before committing. This would converge the streaming and batch outputs on noisy non-CW clips at the cost of one decode period of additional latency. A prototype was implemented and reverted to keep the current behavior surgical and faithful to the batch reference; it is the obvious next iteration.
  • Adaptive trailing-static window. Slow CW (5–8 WPM) has intra-character gaps approaching the current 0.6 s commit gate. An adaptive stable_latency_s = max(0.6, 4 × estimated_dot_period) would let the gate scale with the operator’s speed without manual tuning.
  • Multi-pitch region routing. When two stations share the passband at different pitches, the existing LiveMultiPitchStreamer already separates them at the envelope level. Routing per-pitch envelopes into per-pitch RegionStreamer instances would let us produce two simultaneous transcripts — useful for SO2R and contest monitoring.
  • Confidence and provisional text. The current commit gate is binary: a region is either committed or invisible. A provisional-text channel that surfaces in-flight regions with a confidence band would let the GUI render copy as it forms, without disturbing the committed transcript.
  • Integration into the engine-side CwDecodeService. The decoder presently runs as a subprocess of each UI. Promoting it to a gRPC service in src/rust/qsoripper-server would let multiple clients (Avalonia GUI, web dashboard, future TUI) share a single decoder instance and a single set of region commits.
  • Larger labeled corpus. The strongest protection against regression is a broad, real-world test set. Expanding the existing training-set-a / training-set-b with more multi-burst, mixed-speed, mixed-conditions captures — each with an operator-supplied truth file — is the cheapest way to keep raising the bar.

8. Reproducing the Result

The complete cross-validation can be reproduced from a clean checkout in a few minutes: 

cd C:\Users\randy\Git\qsoripper
cargo build --manifest-path experiments\cw-decoder\Cargo.toml --release

$exe   = "experiments\cw-decoder\target\release\cw-decoder.exe"
$base  = "C:\...\cw-samples\training-set-b"
$f     = "$base\radio-20260502-105714.mp3"
$truth = (Get-Content "$base\radio-20260502-105714.truth.txt" -Raw).Trim()

# Batch reference.
& $exe stream-region --file $f --json --no-realtime `
    --decode-every-ms 250 |
    Select-String '"type":"end"' | Select-Object -Last 1

# Live streaming path used by both UIs.
& $exe stream-live-v3 --file $f --json --region-transcript `
    --decode-every-ms 250 |
    Select-String '"type":"end"' | Select-Object -Last 1

# Both transcript fields should equal $truth:
#   IHU NVCHU 7QP W7N 7QP W7N

9. Conclusion

Multi-burst, mixed-speed off-air CW is a different problem from long single-speed practice files, and it benefits from a different decomposition. By detecting each operator burst as a region, decoding each region independently, and committing only after a trailing-static window, we achieve 100% character-exact transcripts on real-world QSO audio that previously defeated our envelope-only foundation. The architecture preserves the rich visualizer event stream, integrates cleanly into both UI surfaces, and is now the documented baseline against which future CW decoding experiments will be measured. Future work will refine the commit gate, extend to multi-pitch and provisional output, and grow the labeled corpus that protects this baseline from regression.
