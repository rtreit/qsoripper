Region-Isolated Streaming for Real-World CW Copy

This decoder architecture isolates each CW burst before it adds text to the transcript.

Randy Treit, KC7AVA, with the QsoRipper agent toolchain

Abstract. Off-air CW contains speed changes, receiver noise, and long operator pauses. The earlier V3 envelope decoder kept state between CW bursts. That state caused incorrect characters after some speed changes and noise intervals. The new architecture detects each CW burst as a separate region. It decodes each region with an independent pitch and speed estimate. It adds text only after a stable noise interval confirms the end of the region. The target recording produces an exact transcript with this method.

1. Problem

QsoRipper shows live CW data and records a clean transcript. Operators use the transcript for callsigns, contest exchanges, and QSO review. A false word can be worse than an empty result.

The reference recording is radio-20260502-105714.mp3. It contains four off-air CW bursts from a Kenwood TS-590SG. Noise intervals separate the bursts. The approximate speeds are 13, 8, 30, and 30 WPM.

The truth file contains IHU NVCHU 7QP W7N 7QP W7N. The success criterion requires an exact character match through the production live-audio path.

1.1 Earlier V3 envelope decoder

LiveEnvelopeStreamer processes one continuous audio stream. It estimates a Goertzel envelope at the selected pitch. A hysteresis state machine classifies signal intervals. A k-means classifier identifies dits and dahs.

This path gives useful visual data and stable results for long transmissions at one speed. It also supplies cw_decode_rx_wpm for APP_QSORIPPER_RX_WPM.

The reference recording exposed three structural problems:

  • Speed lock: A speed estimate from one burst affected the next burst.
  • Noise floor: Noise between bursts changed the signal threshold.
  • Commit cursor: The append-only cursor kept incorrect text from an early decode cycle.

2. Region-isolated design

An operator burst is a discrete unit. The operator keys the transmitter, sends CW, and releases the key. Receiver noise occurs between bursts. The decoder uses these noise intervals as region boundaries.

1. Detect Find active CW regions in the audio envelope.
2. Isolate Give each region an independent audio window.
3. Decode Estimate pitch, speed, dits, and dahs for that region.
4. Commit Add stable region text to the transcript.

2.1 Region detection

decode_region_stream implements region detection in region_stream.rs. It performs a coarse Goertzel pitch scan. Then it calculates a frame energy envelope at the strongest pitch. 

noise_floor  = quantile(env, 0.30)
signal_floor = quantile(env, 0.95)
threshold    = noise_floor
             + threshold_factor * (signal_floor - noise_floor)

The default threshold_factor is 0.30. Active frames form candidate regions. The detector merges gaps shorter than 0.5 s. It rejects regions shorter than 0.3 s. It adds 0.15 s of padding at each region boundary.

A tonal-prominence test rejects broadband noise. It compares Goertzel power at the selected pitch with broadband frame energy. The default min_tonal_prominence_ratio is 8.0.

2.2 Region decode

The decoder sends each region to the ditdah baseline decoder. Each decode operation starts without state from an earlier region. It calculates a new pitch, dot length, classification, and transcript fragment.

2.3 Streaming wrapper

RegionStreamer in region_streamer.rs keeps a rolling sample buffer. Each try_commit() call runs region detection on that buffer. The decoder commits a region after the stable noise interval. The default stable_latency_s is 0.6 s. 

for region in detected:
    if region.start <= last_committed_end:
        continue
    if region.end > head - stable_latency:
        break
    transcript.append(region.text)
    last_committed_end = region.end

trim_committed() limits memory use during long sessions. It keeps six seconds of audio after the last committed region by default. reset() clears the state after the operator requests a relock.

3. V3 visualizer integration

The V3 envelope path continues to supply waveform, lock, pitch, WPM, and classified-element data. The region path supplies only transcript text. Both paths process the same audio chunks.

Audio source Microphone input or file replay supplies audio chunks.
Envelope path LiveEnvelopeStreamer supplies visual events.
Region path RegionStreamer supplies committed text.
NDJSON output The merged stream keeps the existing client contract.

The --region-transcript option enables the dual path in stream-live-v3. The envelope path continues to emit viz events. The region path controls the cumulative transcript field.

CwDecoderProcessSampleSource uses this option in the production logger. CwDecoderProcess uses it in the experimental visualizer. The client event contract does not change.

5. Limits and future work

5.1 Commit latency

The stable noise interval adds approximately 0.6 s after the key release. This delay is acceptable for logging and QSO review. Fast pileup work can make the delay visible. Operators can change it with --region-stable-latency-s.

5.2 Batch and stream differences

Batch and stream paths call the same decode_region_stream function. The stream path calls it many times on a growing buffer. Noise-only audio can change percentile values as the buffer grows. The tonal-prominence test reduces this risk.

5.3 Future changes

  • Require stable candidate text across multiple decode cycles.
  • Adjust the stable noise interval from the estimated dot period.
  • Route separate pitch tracks to separate region decoders.
  • Supply provisional text without a change to the committed transcript.
  • Move decoding to the engine-side CwDecodeService.
  • Add more labeled recordings with mixed speeds and signal conditions.

6. Reproduce the result

  1. Open PowerShell in the QsoRipper repository.
  2. Build the CW decoder in release configuration.
  3. Set the sample and truth-file paths.
  4. Run the batch command.
  5. Run the live-stream command.
  6. Compare both transcript fields with $truth.
cd C:\Users\randy\Git\qsoripper
cargo build --manifest-path experiments\cw-decoder\Cargo.toml --release

$exe   = "experiments\cw-decoder\target\release\cw-decoder.exe"
$base  = "C:\...\cw-samples\training-set-b"
$f     = "$base\radio-20260502-105714.mp3"
$truth = (Get-Content "$base\radio-20260502-105714.truth.txt" -Raw).Trim()

# Batch reference.
& $exe stream-region --file $f --json --no-realtime `
    --decode-every-ms 250 |
    Select-String '"type":"end"' | Select-Object -Last 1

# Live path used by both user interfaces.
& $exe stream-live-v3 --file $f --json --region-transcript `
    --decode-every-ms 250 |
    Select-String '"type":"end"' | Select-Object -Last 1

# Both transcript fields must equal $truth.
# IHU NVCHU 7QP W7N 7QP W7N

7. Conclusion

Mixed-speed CW needs isolation between operator bursts. The region architecture removes state transfer between these bursts. It preserves the existing visualizer path and client contract. It gives an exact transcript for the reference recording. Future tests must compare all changes with this baseline.
